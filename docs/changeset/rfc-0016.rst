Changeset: RFC-0016
===================

spec/bench.rst
--------------

Replace: Cell
~~~~~~~~~~~~~

Cell
^^^^

A ``Backend`` of agent-exec (``codex`` or ``claude``), a ``model`` and a
``reasoning_effort`` as the backend CLI takes them. The harness condition is
not chosen: a run uses the user's own harness home with whatever kit is
installed there, and the record says which version that was.

Replace: Run
~~~~~~~~~~~~

Run
^^^

One (cell, task, variant, repeat) executed as one ``RunSpec`` of agent-exec:
``JsonStream`` output for codex and ``Json`` for claude so that usage is
parsed from the run itself; ``WorkspaceWrite`` sandbox in the run's working
tree; the user's harness home as it is (codex without
``--ignore-user-config``, claude with the ``Permissions`` isolation); the
guard on; the capture policy of dispatch; the prompt on stdin.

Replace: Isolation
~~~~~~~~~~~~~~~~~~

Isolation
^^^^^^^^^

Every run gets ``<output>/runs/<record-id>/`` with the assembled working tree
in ``work/``, and ``stdout``, ``stderr`` and ``final.md``. The backend runs
in the user's own harness home (``~/.codex``, ``~/.claude``) and reads the
kit, the servers and the credentials installed there; the server reads,
copies, links and logs no credential, and writes nothing into those homes.
What the homes receive is what the backend writes on its own: its session
logs. Hidden tests are never in ``work/`` while the run lasts.

Replace: Record
~~~~~~~~~~~~~~~

Record
^^^^^^

One JSONL line per run with these fields: ``cell`` (backend, model, effort,
and ``kit_version`` read from the kit manifest in the user's harness home
when the run starts, ``null`` when no kit is installed), ``task``,
``benchmark``, ``variant``, ``repeat``, ``cli_versions`` (the backend CLI as
``--version`` printed it), ``argv``, ``started_at`` (UTC), ``wall_ms``,
``exit_code``, ``success``, ``cancelled``, ``run_dir``, ``final_text_path``,
``usage`` (the ``Usage`` buckets of agent-exec, each ``null`` when unknown),
``usage_source``, ``reasoning_tokens``, ``cost_usd`` (``null`` when the model
is not priced), ``price_snapshot`` (the date of the table used) and
``schema_version``. A record whose ``kit_version`` differs from the grid's
first record is noted in the grid's log, so that a kit reinstalled during a
grid is visible.

Replace: Tools
~~~~~~~~~~~~~~

Tools
^^^^^

``bench_grid``
  Input: ``cells`` (one or more), ``task_set`` (path), ``variants`` (``plain``,
  ``documents``, or both; default both where available), ``repeats``
  (default 3), ``output`` (``scratchpad``, ``harness`` or a project path,
  D-25), optional ``tasks`` (a subset by name), optional ``grid_id``,
  ``dry_run``. Starts the grid in the background and returns its identifier
  and the JSONL path. Without ``grid_id`` the identifier is the task set's
  directory name and a hash of the cells, task set, variants, task subset
  and output; ``repeats`` is outside the hash, so raising it extends the
  same grid. A grid whose JSONL already exists resumes: a run whose (cell,
  task, variant, repeat) is present is skipped, a timed-out run included; a
  run recorded as cancelled is run again.

``bench_status``
  Input: ``grid``. Output: runs done, running, skipped and remaining per
  cell, the current run, the last warning, and whether the grid is alive.

``bench_cancel``
  Input: ``grid``, optional ``cell``. Kills the current run of the grid (or
  of the cell) through the guard and marks the remaining runs of the grid or
  cell cancelled; the JSONL keeps every finished record.

``bench_list``
  Output: the grids the server knows with their state and JSONL path.

Replace: Conformance
~~~~~~~~~~~~~~~~~~~~

Conformance
^^^^^^^^^^^

- Synthetic-fixture tests cover the record schema, the cost of a 1-hour
  Anthropic cache write, an OpenAI cached input, a model missing from both
  tables, and resumption after a stopped grid.
- A one-cell grid against a stub backend on ``PATH`` adds nothing to the
  user's harness stores beyond what the backend itself writes, and the
  record's ``kit_version`` is the version of the kit manifest found there
  (``null`` without one).
- No test or code path opens a credential file; the run's argv and
  environment are asserted.
- ``cargo test``, ``clippy -D warnings`` and ``fmt --check`` pass on Linux,
  macOS and Windows.
